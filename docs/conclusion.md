# Вывод

## Рекомендуемый стек

Для публикации результатов вычислительных экспериментов на Python (численные модели, обработка
данных, графики, отчёты с формулами):

| Слой | Выбор | Обоснование |
|---|---|---|
| Генератор | **Sphinx + MyST-Parser** | Максимальный счёт в T1 (87,3 из 100); в P2 — единственный, где все элементы страницы сделаны без ручного HTML и своего кода |
| Исполняемый контент | myst-nb + jupyter-cache | Графики и таблицы пересчитываются из данных при сборке и кэшируются; в отчёт не попадают устаревшие цифры |
| Библиография | sphinxcontrib-bibtex | `{cite:p}`, стили, список литературы; тот же `.bib` годится для LaTeX |
| Вёрстка | Furo + sphinx-design | Тёмная тема, адаптивность, сетки `1 1 2 2` |
| Формулы | MathJax 3, локальный `tex-svg.js` | Без CDN и без отдельных файлов шрифтов: SVG-вывод самодостаточен |
| Интерактивность | Plotly с частичной сборкой (`plotly-basic`) или статичный PNG | Полный plotly.js — 4,7 МБ, две трети веса страницы |
| CI/CD | GitHub Actions: `-W --keep-going` → upload-pages-artifact/deploy-pages + rsync на Helios → `check_site.py` | Строгий режим ловит битые ссылки до деплоя; проверка — по признакам, а не на глаз |
| Зависимости | `requirements.txt` с точными версиями | Воспроизводимость; MkDocs закреплён на 1.x |

## Когда рекомендация меняется

| Ограничение или условие | Что выбрать вместо |
|---|---|
| Итог — статья в PDF/DOCX по ГОСТ, ноутбуки на R или Julia | **Quarto**: CSL-стили, Typst/LaTeX/DOCX из одного `.qmd`, нативные `@fig`/`@tbl`/`@eq` |
| Формул и ссылок на литературу почти нет, важны внешний вид, поиск и скорость старта | **MkDocs Material** — с оговоркой о будущем MkDocs 2.0 и переходе на Zensical: закрепить `mkdocs<2` |
| Команда не знает rST, а grid-таблицы и директивы — барьер | MkDocs Material или Quarto. MyST снимает большую часть rST, но таблицы с объединением ячеек всё ещё через `{eval-rst}` |
| Лабораторный журнал: хронология, теги, RSS, без формул | Pelican допустим, но научную разметку придётся писать самим; лицензия AGPL-3.0 |
| Хостинг отдаёт JS без сжатия (как Helios) и важен мобильный трафик | Убрать интерактивность или `plotly-basic`; MathJax заменить на KaTeX (~280 КБ JS + шрифты) при отказе от `\eqref` |
| Нет доступа к GitHub из сети организации | Тот же workflow на GitVerse или GitLab CI; деплой на Helios (rsync) не зависит от GitHub Pages |
| Можно ставить только пакеты из зеркала PyPI | Sphinx или MkDocs. Quarto есть на PyPI (`quarto-cli`), но это 100 МБ бинарника |

## Ограничения работы

- Quarto в P2 не собирался: его оценки в T1 сделаны по документации.
- Скорость сборки измерена на одной машине (Apple Silicon); в CI абсолютные значения другие,
  но порядок генераторов тот же.
- Оценка Lighthouse Performance на мобильном режиме определяется почти только весом plotly.js и
  MathJax. Это свойство страницы, а не генератора: на одинаковом контенте генераторы отличаются
  на 5–20 баллов.
